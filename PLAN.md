# Plan

Build Story Bridge as a proof of concept with an Express API and React/Vite interface. Stage 1 is the explicitly selected local `file/legacy` backend. Stage 2 adds a fail-closed Supabase account backend, verified bearer identity, private object storage, Google/email-code sign-in, and a display-name profile. No real provider has been configured or tested.

## Files

- `server/index.js`: API, local JSON persistence, authenticated audio access, and static production serving.
- `server/auth.js`, `server/account-routes.js`, `server/supabase-store.js`: explicit mode validation, published-key JWT verification (jose), account API and async Supabase storage interface.
- `server/env.js`, `server/dev.js`, `.env.example`: local ignored environment loading and explicit local file-mode startup.
- `supabase/migrations/202611070001_story_bridge_accounts.sql`: unapplied schema, RLS, private bucket, and storage policy.
- `vite.config.js`: local dev proxy and configurable build output for isolated test builds.
- `src/App.jsx`, `src/main.jsx`, `src/styles.css`: responsive Discover/Listen, account workspace, filtered My stories, profile, story detail, Share, and Review UI.
- `src/components/AppHeader.jsx`, `src/components/AppIcon.jsx`: shared navigation, privacy-safe account menu, responsive five-tab mobile navigation, and inline icons.
- `public/manifest.webmanifest`, `public/sw.js`, `server/sitemap.js`: install metadata, production-only offline app shell, and cached XML sitemap route.
- `src/Landing.jsx`, `src/Brand.jsx`, `public/assets/logo/`, `public/assets/social/`: public landing, brand lockups, waveform motif, and share image.
- `server/story-record.js`: deterministic SHA-256 version fingerprints exposed on story detail; account-mode installs need the additive `version_log` column in the SQL migration.
- `src/RecordingCapture.jsx`, `src/recording.css`: microphone status, elapsed time, captured audio preview, and unsaved recording controls.
- `test/server.test.js`: automated API and access-control tests using isolated `.test-data` storage.
- `scripts/run-browser-tests.js`: isolated two-browser end-to-end checks and screenshot evidence.
- `scripts/capture-product-screens.mjs`: isolated public flow screenshots at 375px, 768px, and 1280px.
- `docs/demo-script.md`, `docs/submission.md`: judge walkthrough and concise capstone description with the feature limits stated.
- `scripts/seed.js`: six fictional public stories in English, French and Swahili for the landing and public feed.
- `README.md`, `AGENTS.md`, `REVIEW.md`: setup, project rules, and final review.

## Steps

1. Create the API and storage model; test privacy, ownership, audio access, and input limits. **Complete.** Stage 1 hardening adds fail-closed store validation, atomic writes with rotating backups, per-IP write limits, per-owner story limits, streamed uploads with a total on-disk cap, proxy trust off by default, restrictive response headers and CSP, generic client errors, and a self-reported checked-by label.
2. Build the browser interface and authenticated private audio playback.
3. Add seed data, run API and browser tests with isolated storage, inspect screenshots at phone and laptop widths, build, and record the review.
4. Improve recording permission, capture, preview, retry, cleanup, and navigation feedback; verify with a fake microphone against isolated data and keep the real-data hashes unchanged.
5. Stage 2 local implementation adds explicit fail-closed backends, account sessions, profile, Supabase storage, atomic database claiming, and a narrow dist-secret check. The continuation adds signed-in create/edit browser coverage through the real account-mode routes and isolated file account store, with a mocked Supabase auth boundary and locally served test JWKS; JWKS redirect/timeout handling is covered locally. **No real provider, project migration, or cloud call has been exercised.** Review findings: `STAGE-2-REVIEW.md`.
6. The local account workspace uses the existing `/api/mine` and public story list. It shows loaded collection totals, draft resumption, filtered/status-labelled stories, and recoverable list/profile errors. Creation and review changes get in-page navigation guards without persistent story caching. The browser checks use synthetic accounts and stories; they do not verify a deployed signed-in flow.
7. Current stabilization adds strict array validation for list API responses, retryable audio loading states, and a dialogue harness whose named handlers are removed after each action. The updated browser scenarios exercise malformed-list retry, private-audio retry, identity races, and profile/workspace recovery with synthetic fixtures.
8. Current product pass adds public landing and feed, four-step share, optional browser-native speech transcript, original-first detail, responsive brand tokens, and story version fingerprints. Browser-native speech recognition support varies.
9. The current AI pass adds an optional server-side OpenAI translation draft service. The storyteller must explicitly approve a generated draft before Share can continue or save it; editing clears approval. The service fails with a manual-translation fallback when no key is configured. Tests mock the provider; no live key or provider call has been verified. Supabase account deployments need `202611080001_add_translation_origin.sql` after the existing Story Bridge migration.
10. An additive Listen cultural-record seed introduces a clearly project-authored Luluwa/Lulua draft with sources and empty French/Tshiluba fields. There is no image pending a file-specific licence check. Restricted records are redacted in the non-owner view. Stories created from the record use a server-side `object_id` field and retain their own fingerprints.
11. `/objects` and `/objects/:id` show four credited Luluwa/Lulua museum reference records. Original photos are preserved, web JPEGs are resized without cropping, and community stories remain separate signed stories. Community-only views redact image and full record for visitors.

Stage 1 hardening is covered by `test/hardening.test.js`, the existing API tests, and isolated browser assertions. The browser run saves responsive screenshots for changed text and checks the CSP with both the recorder preview and playback. See `TEST-REPORT.md` for the latest run and known limitations.

12. Object pages now use docs/object-documentation.md as the source of truth, with English/French knowledge blocks, explicit unknowns, linked sources, shared context, and five community question entry points. Brooklyn credit-line/provenance wording and Berlin date reading are separated and labelled.
13. Phase 1 post composition extends `stories` additively with documentation fields, consent, access, and first-post moderation; `post_media` stores re-encoded image/audio metadata. JPEG/PNG/WebP uploads are signature-checked, converted to WebP (1600px maximum), EXIF-stripped, size-limited and keyed with random names. The first approved post is held private pending admin approval. Fingerprint and version-log code are unchanged.
14. Phase A frontend organization moves screen components to `src/pages/`, audio controls to `src/components/`, shared API and translation labels to `src/lib/`, and app orchestration to `src/state/`. CSS is split across `src/styles/tokens.css`, `src/styles/base.css`, and ordered files under `src/styles/components/`. This pass keeps existing behavior and routes.
15. Phase B stabilization makes first-post admin approval conditional and idempotent across storage adapters, logs only the failing stage and a safe error code, and tests repeated/concurrent approvals. Migration `202611080006_profile_avatar_webp.sql` is confirmed applied. This phase enables Google OAuth locally from `.env`, improves email-code sign-in, adds welcome fields and private re-encoded profile photos, and scopes object questions to their own pages. Real email delivery and Google OAuth still depend on provider configuration and were not verified by synthetic tests.
16. Draft creation now opens its saved review immediately while refreshing the account lists in the background. Private routes show sign-in when no account session is present. The share flow and home title styles also received usability refinements; the isolated browser suite holds the list refresh to verify the review transition does not wait on it.
17. Next navigation pass moves successful sign-in and completed welcome flows to Discover, gives Discover, story details, profile, My stories, and Share stable paths, supports direct story deep links with a working return route, and adds searchable language suggestions plus an explicit Other entry to story creation.
18. Browser verification found that Express 5's named wildcard static fallback did not serve the SPA for direct non-root paths in this environment. The static fallback now uses a regular-expression route so direct page URLs return the app shell; the browser suite covers private and public deep links, signed-in navigation, and browser Back.
19. Phase L0 adds the same app header across the landing and application screens, hides account email everywhere except Profile → Account, moves workspace access into the avatar menu, and adds the five-tab mobile bar. The browser suite checks that a signed-in email is absent from the complete header markup on Discover and Settings while remaining available in Account settings. The manifest and touch icon are linked, static files are served before the SPA fallback, `/sitemap.xml` lists public routes and records, and a production-only service worker fetches pages network-first with the cached shell as an offline fallback. Static assets are cached, `/api/` is never cached, and account and story data remain online-only. The culture directory and client-side search now replace their route placeholders. Notifications have no navigation item or route. **Render serves the pushed L0 build; the live header, `robots.txt`, XML sitemap and manifest were verified on 10 November 2026.**
20. The social schema migration remains owner-reviewed and unapplied; Codex did not run DDL or edit a migration. The current moderation layer adds report, admin queue/statistics, hide, policy, and account-deletion routes using the file-store tests; Supabase reports and report-dependent admin statistics need `202611090007_social_layer.sql` applied first.
21. First-post administration uses the existing admin identity and queue. Only an account whose pending queue request returns 200 sees the Admin menu and page; authorized reviewers can confirm publish or keep-private actions. Pending photo access is session-authenticated and uses private, no-store caching.
22. Story detail reads the full original and translation with author/trust metadata, relative date, credited photos, audio and safe source links. Share uses native share or clipboard and the public detail sets the document title and Open Graph metadata client-side.
23. Translation drafts default to `gpt-6-luna` when no primary model is configured; an optional server-only fallback is tried once for a missing or access-denied model. Provider errors remain generic to storytellers.
24. Final responsive/loading review lazy-loads page routes while keeping the shell and Discover eager. The production build has no Vite size warning and about 158 kB gzip of initial JavaScript. `npm run test:screens` captures 20 screens at 375, 768 and 1280 px; the saved metrics report no horizontal overflow, clipped text, undersized controls or browser console issues for the synthetic guest/account flows. Captures are in `docs/quality/screenshots/2026-11-10-responsive/`; live Lighthouse is run after deployment.
25. Reader-side translation uses Chrome's on-device Translator API when available and links to Google Translate elsewhere. Results are labelled as machine translation and leave the original unchanged; English and French UI labels are provided, with other locales falling back to English. AI draft errors with HTTP 502 include guidance about the reader-side translation button.
26. The Zulu culture card now uses a locally bundled WebP photo of a beaded necklace rather than a people photo. The source is CC0, has no visible person, and its author and source link are recorded in the image data and review manifest.

New posts default to the profile identity; the storyteller can hide name and photo per post and toggle that choice on My stories or story detail. Feed, detail, culture, search and landing cards share the same photo/initials/anonymous icon treatment. API tests cover legacy rows, current profile changes, batching and privacy.
